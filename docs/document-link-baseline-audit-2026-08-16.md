# NRG Technologists — Pre-Migration Document Link Baseline Audit

**Date of audit:** 2026-08-16
**Purpose:** Establish a trustworthy baseline of every historical quote/report/photo document link findable in the five tools' Google Sheets and Drive folders, and confirm which ones currently resolve — *before* any Postgres migration work begins. Anything that breaks after migration but passed here is a real regression. Anything already broken here is a pre-existing issue, not something migration will cause.

**Method:** 100% read-only. Used `read_file_content` / `search_files` to enumerate every Drive-shaped link in the two spreadsheets, `search_files` to fully list both target folders, `get_file_metadata` to confirm each sampled file's existence, and `get_file_permissions` to confirm client-facing sharing (`role: reader`, `type: anyone`) on a spread sample. Nothing was moved, renamed, re-shared, or deleted.

### Sharing anomaly — Historical tab (93 links, 2020–2021 era)

All 93 Historical-tab files **exist** (100% pass on `get_file_metadata`), but permission sampling tells a different story. Sampled 13 of 93, spread across the full date range (Jan 2020 → Jul 2021) and across four different original salespeople/importers:

- **13 of 13 sampled have NO public sharing** — permissions list only the file owner (`projects@nrgtechnologists.com`), no `role: reader, type: anyone` entry at all.
- By contrast, every 2022+ file sampled in the current Quote Generator output folder (Source 3) — including files created by the same `projects@nrgtechnologists.com` owner — **does** have `anyone: reader` sharing.

This means: if a client received one of these `...uc?export=download&id=...` links via WhatsApp/email back in 2020–2021, clicking it **today already returns a Google "you need permission" screen**, not the PDF — a pre-existing problem, not something migration would newly break, but exactly the scenario the owner is most afraid of, already live. Because the pattern was 13/13 with no exceptions and a very sharp before/after boundary (no Historical-tab file has it; every later folder file does), it is reasonable to treat all 93 Historical-tab links as very likely affected, though only the 13 sampled were directly confirmed.

Sampled Historical file IDs (all owner-only, no public link): `1LvxSxjxmrN_2VnH1OmrFizus66bcqnJe`, `10EOcz_wuEcfgU-Qa0XKdznh20SLF3OiA`, `1JIZA7fHe7Yehpb9JpZHyAZ17cHW9JWY3`, `1GSiWVw_nPovpmKrUxKGLAAe8KG-ECRhk`, `1BKSDPxC2fi4KVBT4G3qZwUp3-YQHDHWm`, `1njY38J77sKaCGOTELJ7FEEkjGNdee9R9`, `1bb_x5oTwjdpjyB7aIy5I3uQ4wGylILzA`, `1JgEOVM9_eoFREbS5_9hIpzf4vPDcDnuE`, `1upIbXklWeajsC20B0TzdmQ1B6fniUCEn`, `1VzYzvS-bbB76wiBd1e9VGEDl8NR8pzm4`, `1aPCylbFBPqZ2_NrbYu08VXvsrdPAIvXY`, `1Sgj3RKAN_eaHs6iTddzoM9ekUxX4DMGO`, `1krA7EplbX3MhKbzZwg7s6Ufj2VGFGEi9`.

## What this audit did NOT cover (be honest about the boundary)

- **Source 2 (AMC/Service Desk) link checking was much shallower than Source 1.** Only ~21% of its 191 distinct links (40 of 191) had existence directly confirmed, and only 11 had sharing sampled. The Service-quotes tab in particular had only 15 of 53 (28%) checked. **No failures were found in what was checked**, but 79% of Source 2's links were never individually verified — a failure rate similar to Source 1's dashboard tab (about 4%) could exist undetected in the unchecked 151 links.
- **Source 3's 900 "orphan" files** (present in the folder, no matching current sheet row) were spot-checked for plausibility (dates, naming pattern) but not individually opened or permission-checked one by one — only 7 of the folder's 1,057 files got a permissions check.
- **The Historical-tab sharing anomaly is a strong inference (13/13 sampled), not a 93/93 direct confirmation.** The other 80 Historical-tab files were not individually permission-checked.
- **Ticket-photo folders' intended audience was not verified.** This audit flagged that `PHOTO_FOLDER_URL` folders lack public sharing but could not confirm from this session alone whether those folders are ever actually sent to clients (vs. purely internal engineer references) — that would change how urgently it needs fixing.
- **The two "NRG Service Report" monthly PDF summaries and the "NRG Service Desk" root folder** (found during the Source 5 search) were noted but not audited — they aren't referenced by any spreadsheet row, so they fell outside "document links currently claimed by the tools."
- **Prospect Intelligence's live script binding was not independently confirmed** (see Source 6 caveat) — high confidence, not proof.
- **No Solar Bill Analyser anomalies were found**, but its entire population (46 files) is only 8 days old — this baseline cannot speak to whether older Solar Bill Analyser output (if any ever existed before Aug 8) has the same clean sharing pattern, because none was found.
- This audit did not attempt to actually click/download any link as an anonymous/external user to double-confirm the "anyone: reader" permission behaves as expected in practice — it relied on the Drive API's permissions listing, which is the authoritative source but is one level removed from an end-to-end client experience test.
